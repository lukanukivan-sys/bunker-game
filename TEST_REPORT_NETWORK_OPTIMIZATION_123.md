# Звіт перевірки етапу 18 — мережева оптимізація

## Реалізовано

- Довге опитування стану з очікуванням зміни `revision` до 20–25 секунд.
- Миттєве пробудження запитів після `touch(room)`.
- Серверний heartbeat під час відкритого довгого запиту.
- Адаптивне повторення запитів із `AbortController`, експоненційною затримкою та `Retry-After`.
- Окремі token-bucket бюджети для `state`, `action`, `auth`, `read`, `write`.
- Персональний бюджет `IP + playerId` і великий спільний NAT-бюджет.
- Сумісність старих клієнтів без `X-Player-Id` для POST-дій.
- ETag і відповіді `304` для статичних файлів.
- Мережеві метрики в `/api/health`.

## Навантажувальний сценарій

- 12 одночасних клієнтів з адреси `127.0.0.1`.
- 12 довгих запитів прокинулися після однієї дії приблизно за 0,26–0,27 секунди.
- Відкритий 13-секундний запит підтримав статус гравця «підключено» після порога 12 секунд.
- 480 додаткових читань стану не зіткнулися зі старим спільним обмеженням 360 запитів за хвилину.
- 96 POST-дій пройшли незалежно від бюджету читання.
- Надмірно активний клієнт отримав `429`, але інший гравець за тією самою IP продовжив отримувати `200`.
- Повторне завантаження `app.js` із ETag повернуло `304`.

## Регресія

Успішно перевірено 27 тестових файлів, включно з усіма попередніми етапами:

- режими й модулі;
- детектив;
- умови перемоги;
- стратегічні розкриття;
- демографічні обставини;
- трибунал;
- пояснення шансів;
- командні операції;
- медичні дилеми;
- зовнішній табір;
- автоматичний ведучий;
- передавання хоста й повторний вхід;
- фінальна симуляція;
- кампанії, профілі та збереження.

Контент усіх семи сетингів пройшов `validate_content.js`. Серверний і клієнтський JavaScript пройшли `node --check`. В основному HTML знайдено 329 ID, усі унікальні.
