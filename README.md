# СХОВИЩЕ 1.2.10

Мережева браузерна соціально-стратегічна гра для 4–12 учасників. Сервер працює на Node.js 20+ без зовнішніх npm-залежностей.

## Версії та сумісність

| Компонент | Поточна схема |
|---|---|
| Продукт | `1.2.10` |
| Кімнати | `rooms-v6` |
| Генерація | `1.2.9-g2` |
| Контент | `content-1.2.9-c1` |
| Платформа профілів | `platform-v2` |

Версії централізовано визначені у `config/version.js`. Seed відтворює стартову роздачу лише за однакових конфігурації, схеми генерації, версії контенту та кампанійної спадщини.

## Основні режими

- **Класичний відбір:** розкриття → дискусія → рішення хоста щодо кризи → одне загальне голосування → наслідки.
- **Спільне виживання:** планування → операції → командне рішення щодо кризи → наслідки.
- **Фракції:** переговори → прихована дія → таємне голосування → наслідки.
- **Детектив:** приватне розслідування → обговорення → формальне звинувачення → розв’язка.
- **Розширена гра:** базовий цикл із не більш як двома сумісними додатковими модулями.

Конфігураційний валідатор не дозволяє поєднання, що створюють конфліктні цикли. Фракції примусово використовують таємне голосування. Повний автохост доступний лише для простих пресетів; у складних конфігураціях він переходить у режим помічника.

## Ключові зміни 1.2.9–1.2.10

- ізольована генерація за seed без глобальної підміни `Math.random`;
- один обов’язковий загальний бюлетень за раунд у режимах із вигнанням;
- централізовані правила участі в рішеннях, ізоляції та позбавлення голосу;
- довгостроковий прогноз відокремлений від основного результату партії;
- точні внутрішні теги компетенцій не передаються гравцям;
- усі 105 здібностей мають формалізований профіль сили й узгоджений опис;
- гарантовані успіхи та безкоштовне втручання в голосування замінено на сильні, але ризиковані ефекти;
- ресурси для гравців показуються категоріями, точні числа залишаються хосту;
- екран створення поділено на швидкі, звичайні й експертні параметри;
- під час партії використовується до чотирьох основних вкладок, а актуальна дія дублюється на вкладці «Хід»;
- журнал має фільтри та короткий підсумок раунду;
- додано редакторський аудит контенту й аудит балансу здібностей.

Останні релізні виправлення: `IMPLEMENTED_FIXES_1.2.10.md`. Повний тестовий звіт: `TEST_REPORT_1.2.10.md`.

## Збереження

Активні кімнати зберігаються окремими атомарними файлами:

```text
data/rooms-v6/<ROOM_CODE>.json
data/rooms-v6.json
data/backups/
```

Сервер:

- мігрує старий `data/rooms_v105.json`, якщо нових кімнат ще немає;
- ізолює пошкоджений файл однієї кімнати від інших;
- видаляє завершені або покинуті кімнати після TTL;
- створює обмежену кількість резервних копій;
- записує кімнати й резервні копії асинхронно;
- зберігає дані при штатному завершенні.

Профілі, кампанії, набори контенту й статистика зберігаються окремо у папці `data`.

> Поточне файлове сховище розраховане на один приватний або малий публічний екземпляр Node.js. Для горизонтального масштабування потрібна спільна SQLite/PostgreSQL-база та централізовані сеанси.

## Облікові записи та безпека

- мінімум 10 символів у паролі та базова перевірка складності;
- затримка й тимчасове блокування після серії невдалих входів;
- кілька активних сеансів із можливістю перегляду та відкликання;
- резервний код для скидання пароля;
- `Content-Security-Policy`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, заборона iframe;
- окремі ліміти тіла запиту для входу, дій кімнати та імпорту наборів;
- токени облікових записів не передаються у query-параметрах і не зберігаються у `localStorage`.

У браузерній версії токени зберігаються в `sessionStorage` та передаються заголовками. Для великого хмарного сервісу наступним кроком мають бути захищені `HttpOnly; Secure; SameSite` cookie.

## Запуск

Звичайний локальний сервер:

```text
start_server.bat
```

Постійний сервер з автоматичним перезапуском:

```text
start_persistent_server.bat
```

Через LocalTunnel:

```text
start_internet.bat
```

Після запуску:

- гра: `http://localhost:3000`;
- кабінет: `http://localhost:3000/manage.html`;
- стан сервера: `http://localhost:3000/api/health`.

## Перевірки

Повний тестовий прогін:

```text
npm test
```

Окремі групи:

```text
npm run test:unit
npm run test:smoke
npm run test:network
```

Контентні аудити:

```text
npm run audit
```

`run_all_tests.js` автоматично знаходить 35 сценаріїв, запускає їх окремими процесами, чекає реального закриття дочірніх серверів, контролює тайм-аут і повертає код `0` лише після успішного проходження всього набору.

## Структура

```text
config/version.js          централізовані версії й схеми
lib/random.js              ізольований відтворюваний RNG
lib/security.js            HTTP-заголовки безпеки
lib/room_store.js          атомарне сховище кімнат і міграція
content/                   базовий та авторський контент
content/ability_balance.js профілі й описи здібностей
public/                    клієнтський інтерфейс
scripts/                   редакторські та балансові аудити
reports/                   результати аудитів
server.js                  HTTP API та оркестрація ігрових доменів
```

`server.js` усе ще містить значну частину оркестрації режимів. Найризикованіші наскрізні компоненти вже винесені у модулі, але повне розділення маршрутів, фаз, голосування, медицини, експедицій і детективу потребує окремої поетапної міграції з контрактними тестами.
