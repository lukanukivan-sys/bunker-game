# Як створювати авторський контент для «Сховища»

Авторський набір **додається до базового контенту**, а не замінює його. Найзручніше працювати через `manage.html` — сторінку «Кабінет».

## 1. Створіть профіль

1. Відкрийте гру.
2. Натисніть **«Кабінет»**.
3. Створіть локальний профіль або увійдіть у наявний.
4. Перейдіть у вкладку **«Контент»**.

Профілі та набори зберігаються на конкретному сервері. Якщо ви опублікували гру на Render, набори зберігаються в його постійному сховищі даних, якщо воно підключене.

## 2. Простий контент: по одному запису в рядку

Через звичайний редактор можна додати:

- походження;
- професії;
- здоров’я;
- навички;
- предмети;
- таємниці;
- риси;
- хобі;
- фобії;
- аномалії;
- взаємини.

Формат:

```text
Польовий лікар
Ремонтник дронів | odd
Насправді три єноти | absurd
```

Рівні:

- `normal` — серйозний або звичайний запис;
- `odd` — дивний, але ще правдоподібний;
- `absurd` — комедійний запис для високого рівня абсурдності та «Повного хаосу».

Якщо рівень не вказано, використовується `normal`.

## 3. Повний JSON набору

Мінімальна структура:

```json
{
  "name": "Мій набір",
  "description": "Короткий опис набору",
  "setting": "modern",
  "public": false,
  "entries": {
    "origins": [],
    "professions": [],
    "health": [],
    "skills": [],
    "items": [],
    "secrets": [],
    "traits": [],
    "hobbies": [],
    "phobias": [],
    "anomalies": [],
    "relationships": [],
    "catastrophes": [],
    "shelters": [],
    "events": [],
    "expeditions": []
  }
}
```

Допустимі значення `setting`:

```text
all
modern
fantasy
space
postapocalypse
cyberpunk
horror
detective
```

`all` означає, що набір можна обрати в будь-якому сетингу.

## 4. Катастрофа

```json
{
  "title": "Повстання побутової техніки",
  "description": "Розумні чайники, пилососи й холодильники об’єдналися у профспілку.",
  "threat": "Автономна побутова техніка",
  "level": "absurd"
}
```

Обов’язково:

- `title` — назва;
- `description` — що сталося;
- `threat` — коротка головна загроза.

Рекомендована довжина опису: 150–400 символів.

## 5. Сховище

```json
{
  "title": "Підземний супермаркет",
  "description": "Великий торговий комплекс зі складами та службовими тунелями.",
  "modules": [
    "Вентиляція",
    "Генератор",
    "Вода",
    "Холодильні склади",
    "Аптека",
    "Службові тунелі"
  ],
  "areaM2": 3200,
  "roomCount": 18,
  "rooms": ["Склад", "Їдальня", "Медпункт", "Майстерня"],
  "provisions": ["Консерви", "Вода", "Побутова хімія"],
  "initialResources": {
    "food": 68,
    "water": 54,
    "energy": 48,
    "medicine": 42,
    "integrity": 62,
    "morale": 55
  }
}
```

Для сховища потрібен хоча б один модуль. Практично краще використовувати 4–10 модулів.

## 6. Подія

```json
{
  "id": "singing_filter",
  "title": "Фільтр почав співати гімн",
  "description": "Вентиляція працює, але кожні п’ять хвилин виконує гімн невідомої держави.",
  "level": "absurd",
  "choices": [
    {
      "id": "repair",
      "label": "Розібрати панель і полагодити",
      "success": 0.68,
      "good": {
        "integrity": 5,
        "morale": 2
      },
      "bad": {
        "energy": -7,
        "morale": -4
      },
      "goodText": "Система замовкла й почала працювати стабільніше.",
      "badText": "Гімн став голоснішим, а панель втратила частину живлення."
    },
    {
      "id": "choir",
      "label": "Створити хор і співати разом",
      "success": 0.58,
      "good": {
        "morale": 9
      },
      "bad": {
        "morale": -5,
        "energy": -2
      },
      "goodText": "Спільний спів підняв мораль.",
      "badText": "Хор пересварився через неправильний другий куплет."
    }
  ]
}
```

Правила:

- `id` пишіть латиницею, цифрами, `_` або `-`;
- у події має бути щонайменше два рішення;
- кожне рішення має власний унікальний `id`;
- `success` — число від `0.05` до `0.98`;
- `good` — наслідки успіху;
- `bad` — наслідки невдачі;
- `goodText` і `badText` пояснюють результат у журналі.

Підтримувані механічні ключі події:

```text
food
water
energy
integrity
medicine
morale
allies
assets
```

Приклад знахідки:

```json
"good": {
  "assets": "Ручний аналізатор повітря",
  "morale": 2
}
```

### Як не зробити однозначно найкращий вибір

Погано:

- найвищий шанс;
- найбільша нагорода;
- найменший штраф;
- немає ціни.

Добре, коли різні рішення мають різні переваги:

- безпечне, але дороге;
- ризиковане, але вигідне;
- дешеве, але з довгостроковим штрафом;
- морально сумнівне, але практичне.

## 7. Експедиція

```json
{
  "id": "strange_vending_machine",
  "name": "Автомат із підозріло свіжими батончиками",
  "description": "Автомат працює посеред зруйнованого вокзалу й приймає монети держави, якої ніколи не існувало.",
  "tags": ["technical", "survival", "social"],
  "difficulty": 3,
  "level": "absurd",
  "success": {
    "food": 12,
    "morale": 4
  },
  "failure": {
    "energy": -4,
    "morale": -3
  },
  "asset": {
    "name": "Інструкція до автоматів",
    "description": "Допомагає знаходити приховані сервісні режими."
  }
}
```

Правила:

- `difficulty` — ціле число від 1 до 6;
- бажано 2–4 теги;
- нагорода задається в `success`;
- штраф — у `failure`;
- `asset` необов’язковий.

Типові теги можна подивитися внизу звіту аналізатора. Найчастіше використовуються:

```text
medicine
survival
investigation
water
technical
science
defense
social
food
energy
repair
navigation
magic
stealth
```

Новий тег не заборонений, але базові професії та навички можуть не давати для нього бонусу.

## 8. Аналізатор якості

Кнопка **«Аналізувати»** перевіряє чернетку без збереження.

Він шукає:

- порожні записи;
- неправильні рівні `normal/odd/absurd`;
- занадто довгі назви та описи;
- схожі записи всередині набору;
- схожість із базовим контентом;
- відсутні теги експедицій;
- невідомі теги;
- надто сильні нагороди;
- надто каральні штрафи;
- події з очевидно найкращим рішенням;
- слабку тематичну впізнаваність сетингу;
- ризик частих повторів у тестовій генерації.

Рівні звіту:

- **Помилка** — структура може не зберегтися або не працювати;
- **Попередження** — контент працездатний, але може бути незручним чи незбалансованим;
- **Порада** — евристична рекомендація, яку можна свідомо проігнорувати.

Аналізатор нічого не змінює автоматично.

## 9. Тестова генерація

Можна згенерувати 10, 25, 50 або 100 тестових персонажів.

Звіт показує:

- скільки разів авторські записи потрапили до карток;
- ризик повторення малої категорії;
- кілька прикладів сформованих карток;
- категорії, де власного контенту ще мало.

Авторський набір додається до базового, тому невеликий пакет не з’являтиметься в кожній картці.

## 10. Збереження, експорт та підключення

1. Натисніть **«Зберегти набір»**.
2. За потреби натисніть **«Експорт»** — отримаєте JSON-файл.
3. На сторінці створення кімнати знайдіть поле **«Авторський набір»**.
4. Виберіть свій набір.
5. Запустіть партію.

Приватний набір бачить лише його автор. Публічний набір доступний усім профілям цього сервера.

## 11. Безпечний робочий процес

1. Спочатку створіть 10–20 простих записів.
2. Проведіть тестову генерацію на 25 карток.
3. Виправте явні повтори.
4. Додайте 2–4 події та експедиції.
5. Перевірте, чи немає однозначно найкращих рішень.
6. Зіграйте коротку партію з окремим seed.
7. Експортуйте резервну копію JSON.
8. Лише після цього робіть набір публічним.

## 12. Обмеження

- максимум 3000 записів в одному наборі;
- максимум 250 записів у кожній розширеній категорії;
- редактор не виконує довільний JavaScript;
- авторський контент не може змінювати серверний код;
- точні дублікати простих записів під час збереження прибираються;
- аналіз схожості та балансу є евристичним, а не абсолютною оцінкою якості.
