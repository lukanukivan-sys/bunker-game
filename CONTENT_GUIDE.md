# Авторські набори у «Сховищі» 1.0.5

Найбезпечніший спосіб додавати власний контент — сторінка `manage.html`.

## Простий формат

Кожен рядок — окремий запис:

```text
Польовий лікар
Ремонтник дронів | odd
Насправді три єноти | absurd
```

Допустимі рівні: `normal`, `odd`, `absurd`.

## Структура JSON

```json
{
  "name": "Мій набір",
  "setting": "modern",
  "public": false,
  "entries": {
    "professions": [{ "name": "Польовий лікар", "level": "normal" }],
    "skills": [{ "name": "Ремонт фільтрів", "level": "normal" }],
    "events": [],
    "expeditions": [],
    "catastrophes": [],
    "shelters": []
  }
}
```

`setting` може бути одним із: `all`, `modern`, `fantasy`, `space`, `postapocalypse`, `cyberpunk`, `horror`, `detective`.

## Захист від конфліктів

Під час імпорту сервер:

- прибирає точні дублікати звичайних записів;
- перевіряє рівні абсурдності;
- перевіряє унікальність ID подій, їхніх рішень та експедицій;
- обмежує складність експедицій значеннями 1–6;
- вимагає щонайменше два рішення для події;
- вимагає модулі для власного сховища;
- не дозволяє набору містити понад 3000 записів.

Авторський набір зберігається окремо й не змінює базовий контент гри.


## Додаткові категорії детективного сетингу

У `content/detective.js` використовуються окремі масиви:

```text
alibis
motives
access
testimonies
evidenceLinks
```

Кожен запис має стандартний формат `{ name, level }`. Не записуйте в один елемент одразу висновок про вину. Алібі, мотив і доказ повинні бути окремими фактами, які можуть суперечити одне одному.

Винуватець не додається вручну до `secrets`: сервер призначає його під час старту партії й узгоджує приховану роль із алібі, доступом та зв’язком із доказами.
